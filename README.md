# AI 协作开发模板（ai-dev-template）

一套从三个真实项目里提炼出来的**通用工程模板**，解决三个问题：

1. **AI 怎么知道这个项目的规矩？** → `AGENTS.md`（通用约定 + 项目业务约定骨架）
2. **人怎么把需求说清楚？** → `PROMPT_TEMPLATE.md`（场景化提示词模板）
3. **项目怎么从需求走到上线？** → `DEV_WORKFLOW.md`（流程与质量门禁）+ `DEPLOY.md`（部署手册模板）

> 来源：`AutomatedDispatchSystem`（陪易玩，移动端 H5）、`BackendManagementFramework`（多租户后台框架）、`jisu-ai-customer`（AI 客服）。
> 不是理论文档，每条规则都对应三个项目里真实踩过的坑。

## 文件说明

| 文件 | 给谁看 | 内容 |
| ---- | ------ | ---- |
| [`AGENTS.md`](./AGENTS.md) | AI + 未来的自己 | 工程形态、目录基线、技术栈矩阵、12 条硬性安全规则、代码风格、Swagger 规范、安全基线、数据库迁移、测试门禁、文档组织、部署约定、AI 协作规则、项目业务部分骨架、交付自检清单 |

## 快速开始

### 新项目

```bash
# 1) 建项目骨架（client/ + server/ + docs/ + DEPLOY.md + AGENTS.md）
# 2) 复制 AGENTS.md 到项目根，保留 §1–§11，按 §13 填写第二部分（业务定制）
# 3) 复制 DEPLOY.md 到项目根，替换 {{占位符}}，删掉不适用的部署方式
# 4) 开工第一句话用 PROMPT_TEMPLATE.md 的「通用开场」+
#    「2.1 新项目从零搭建」或「2.2 新需求实现」
# 5) 按 DEV_WORKFLOW.md 的 S0–S12 推进，两个 ★ 闸门不放行不继续
```

### 已有项目

1. 用 `AGENTS.md` §1–§11 逐条对照，缺什么补什么（尤其第二部分业务约定）。
2. 用 `DEV_WORKFLOW.md` §4 质量门禁表，把命令补进项目根 README 或 CI。
3. 用 `DEPLOY.md` 的章节结构对照现有部署文档，缺的章节补上（验收清单和踩坑记录最容易缺）。

## 使用原则

- 优先用**项目内自己的 `AGENTS.md`**；本模板只是基线（优先级：项目约定 > 本模板 > 默认习惯）。
- **不要为了统一去改项目已定的技术栈**；统一的是约定与流程。
- 模板里的 `{{占位符}}` 必须替换；`〔可选〕` 章节按项目保留或删除，别留一堆没用到的方案。
- 踩过的坑写回对应项目的记录表（`AGENTS.md` 第 13/14 节、`DEPLOY.md` 第 12 节），否则下次还会踩。


## 维护

- 新增规则前先问：它是否已经在某个真实项目里导致过问题？没有就先别加。
- 改完在对应项目里同步一次（模板和实际约定不能两套）。
- 建议在稳定后打 tag（如 `v1.0`），并在提交信息里写清「模板改了哪条、为什么」。
